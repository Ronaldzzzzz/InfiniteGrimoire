# 《Infinite Grimoire：無限魔導書》遊戲企劃與設計規格大綱

## 一、 遊戲概述 (Game Overview)

* **遊戲名稱**：
  * **英文**：*Infinite Grimoire*
  * **中文**：*《無限魔導書》*
* **副標題（可選）**：*Echoes of Alchemy / 殘卷與嬗變之秘*
* **遊戲類型**：極簡像素放置合成 × 機率煉金探索 (Minimalist Pixel Idle-Merge Alchemy)
* **目標平台**：Web / 行動端與桌面端自適應網頁（支援一鍵存檔至 LocalStorage，便於社群鏈接直接遊玩）
* **核心基調**：極簡像素美學、神秘晦澀的魔法書卷感、強烈的不確定性與「稀有出貨」成就感。

---

## 二、 核心設計定位與特色

1. **玩法融合 (1: A+D)**：
   * **放置增生 (Idle/Merge)**：基礎元素與魔素會隨時間凝聚（或透過法陣生成器產生），支援自動化或點擊產出。
   * **自由拖曳碰撞合成 (Infinite/Discovery Craft)**：將任意兩件素材拖曳至煉金大鍋／法陣中央進行嬗變合成。
2. **開發架構 (2: A)**：
   * **純前端靜態部署，預製海量合成樹**：由 AI 在開發期離線生成龐大的多層級合成網絡（例如 300~1000+ 種配方）、像素圖標、詞條與風味文本。無雲端 API 成本、低延遲、離線即玩。
3. **視覺與呈現風格 (3: 否 - 極簡像素風)**：
   * 1-bit / Pico-8 復古低像素色調（深邃黑夜背景配復古符文綠/琥珀金色）。
   * 界面模仿古老但整潔的魔導書卷或煉金術士工作台，沒有多餘裝飾，專注於圖標、符文特效與文字反饋。
4. **體驗節奏 (4: B - 中輕度 Casual RPG / 累積型)**：
   * 遊戲流程可維持 1~3 小時以上的漸進探索期，具備離線收益、天賦加點（提升幸運值、產出速度、槽位上限）與階梯式圖鑑解鎖。
5. **社群傳播性 (5: 是)**：
   * **「禁忌配方卡」一鍵生成**：玩家煉成 SSR 稀有魔法或素材時，可直接導出包含像素動畫、配方公式、幸運幾率、玩家代號的精緻截圖卡片，直推 Threads / X / Discord。

## 三、 核心玩法與數值機制

### 1. 核心循環 (The Core Loop)
```
[魔力源泉/符文石] ──(放置產出)──> [基礎元素] (火/水/風/土/以太)
                                   │
                                   ▼
 [隱藏/殘破配方] ──(合成嘗試)──> [雙元/多元嬗變]
                                   │
             ┌─────────────────────┴─────────────────────┐
             ▼ (常規結果)                                 ▼ (觸發低機率變異)
       [一般產物 / 廢渣]                            [稀有/SSR 秘術與神性素材]
             │                                           │
             └─────────────> [解鎖魔導書圖鑑] <─────────┘
                                   │
                             [獲得賢者之石點數]
                                   ▼
                          [升級天賦：提高幸運與產速]
```

### 2. 機率與變異機制 (Probabilistic Alchemy)
* **固定公式 vs 機率分支**：
  * 例如：`[火元素]` + `[黑曜石]`：
    * 70% 產出：`[熔岩精粹]`（常規）
    * 25% 產出：`[熾炎符文]`（優秀）
    * 4.9% 產出：`[真理之火 (SSR)]`（極稀有）
    * 0.1% 產出：`[墜毀的星核 (UR)]`（傳說）
* **合成「殘卷與線索」系統**：
  * **不提供完整公式手冊**：玩家在探索圖鑑時，只會看到模糊線索（如：*「據說當純粹的深淵與熾烈相遇時，有 1% 的機會誕生虛空烈焰……」*）。
  * 玩家每次嘗試合成，即使失敗或產生次級產物，系統也會記錄**「該組合已嘗試過」**並動態顯示歷史出貨機率，激發收集與解密慾望。

## 四、 巨量配方結構分層設計 (範例架構)

| 階層 (Tier) | 類型 | 範例素材 | 特性與機率 |
| :--- | :--- | :--- | :--- |
| **Tier 0** | 始源物質 | 原初魔素、水銀、硫磺、鹽 | 放置源泉無限產出 |
| **Tier 1** | 自然元素 | 霜凍、烈焰、靈氣、暗影、岩石 | 兩兩基本融合，100% 成功 |
| **Tier 2** | 魔藥與金屬 | 賢者之水、秘銀、以太溶劑、催化粉末 | 開始引入 20%~30% 失敗/分支機率 |
| **Tier 3** | 高階符印與奇物 | 凝固時光、克拉肯之血、虛空結晶 | 需多重前置合成，關鍵產物機率 5%~10% |
| **Tier 4 (SSR)** | 禁忌禁術 | 永恆烈陽、維度裂隙、靈魂重塑 | 0.5%~1% 超稀有變異出貨，解鎖全屏像素粒子震撼 |

## 五、 技術選型與開發步驟建議

1. **前端架構**：
   * **框架**：React / Vue 3 或純 Vite + Canvas/Pixi.js。
   * **像素渲染**：使用 CSS Pixel-art 濾鏡或小尺寸 Canvas 配合 `image-rendering: pixelated`。
   * **狀態儲存**：`localStorage` + 匯出/匯入 Base64 存檔代碼（便於跨裝置繼承）。
2. **AI 在開發期的具體協作流程**：
   * **配方矩陣生成**：利用 Claude / GPT 生成龐大的 JSON 數據表（包含 `id`, `name_zh`, `name_en`, `tier`, `recipe: [itemA, itemB]`, `outcomes: [{id, rate}]`, `flavor_text`）。
   * **像素圖標產出**：使用 Midjourney / DALL-E 生成 16x16 或 32x32 像素精靈圖表，再經腳本批次切割。
   * **代碼撰寫**：可交由 AI 完成整個拖曳放置 (Drag-and-Drop) 引擎與合成校驗邏輯。
