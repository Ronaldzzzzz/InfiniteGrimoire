## 1. 目的

使用者：「完全體會不到自己是魔法師的感覺」。合成要變成遊戲的主角：在一張牛皮紙上親手畫出魔法陣，按下合成、注入魔力，在未知中揭曉魔法。這個專案把「兩個輸入的合成台」換成魔法陣，把技能樹換成會長大的星圖（魔導書），並讓魔法陣合出來的魔法直接變成戰鬥長帶上的效果。

使用者描述的那一刻（原話）：

> 在一張桌子上，張開了一張略帶破舊的牛皮紙。張開後映入眼前的是空白的一個圓圈。選取核心的同時，中心的牛皮紙用帶有繪畫的方式將火元素帶入圓圈，後續依序選擇環、節點、符文等。全部選取完成後，一個完整的魔法陣出現在眼前。按下合成開始注入魔力，出現圓形的跑條，在這過程中畫面出現魔法的特效如火花、閃光等。跑滿的時候出現一同出現結果。

**範圍（使用者 2026-10-30）：** 「不需要一口氣完成全地圖的改動。目前遊戲都未上線，只需要先把核心功能做出來。但如果怪物打不動有明顯瑕疵我在試玩的時候會再叫你拓展一點。」「先著重在系統與核心功能，數值等之類的問題之前有説先暫時跳過。」
- 這個專案的重心是**系統**：魔法陣的資料與規則、陣 → 魔法的產生、伺服器合成、牛皮紙介面、星圖魔導書、格子與符文的開放。
- **內容先做最少**：名魔法（教科書）先做第 2.5 節的範例與每個屬性、每段階級足以推圖的少量魔法；其餘名魔法之後補。
- **數值先暫定**：只要每條路線推得動、測試把關的規則成立（強度曲線方向、0 次被拒）即可；平衡留到之後。試玩時發現怪打不動等明顯問題，再依使用者指示擴充。

## 2. 使用者拍板

### 2.1 擺放與合成的過程
- 牛皮紙上先是空白的圓圈；選核心時，紙中央以「畫上去」的方式出現該元素；之後選環、節點、符文，每一步都畫到紙上；全部選完是一個完整的魔法陣。
- **隨時可以回頭改**，核心也可以，沒有強制順序。一切由伺服器計算機率，不論玩家怎麼改，結果都自行承擔。
- 按下合成：注入魔力，魔法陣周圍出現**圓形進度條**，過程中有火花、閃光等魔法特效；跑滿時結果與特效一起出現。
- 注入時間**暫定 3 秒**；只有發生**異變**時改為 **5 秒**（專案 2 的「稀有」結果也用 5 秒，見 3.9）。
- 按下合成前不花任何東西（總體設計已定）。

### 2.2 陣上每一部分決定什麼
- **環與節點越多，規模越大**（＝總體設計的「階級＝節點數」）。
- **符文決定形態**。
- 以下三項是設計者提出、使用者同意「先照這樣定」：核心元素＝主屬性；節點上的元素＝附加效果（火燃燒、風擊退、水潮濕、土緩速、雷連鎖；同種越多越強）；相生＝加成，相剋＝削弱或反應（總體設計已定兩者都可能）。

### 2.3 符文
- **一個環只能選一種符文**（整環同一個樣式）。
- 不同環選了不同符文（例：一環「射」、二環「爆」）：一般結果**各 50% 擇一**（三種就各 1/3，設計者推論）。
- 只有**異變、大成功**時才會**相加、增強、或兩者都不是**（屬於專案 3；見 4）。
- 符文**從魔王、任務取得**；**使用符文不消耗素材**。之後可能改為「繪製要消耗素材或物品」（這次不做，但資料結構要留空間）。

### 2.4 什麼算「同一個魔法」
- 魔法＝**陣的配置＋實際出來的形態**。同一個陣出了「射」和「爆」，是**兩個不同的魔法**，魔導書各記一筆；再出一次同樣的，若品質較好就更新（品質在專案 3）。
- 因此**同一魔法可以有多個魔法陣**合出來。魔導書呈現時，把陣**標準化**：例如它是「射」，就把所有環的符文都畫成「射」。

### 2.5 名魔法
- 預計把**大多數**現有名魔法做成魔法陣（教科書），但這個專案只先做少量（見「範圍」）。

## 3. 設計者決定（使用者已看過清單並同意「沒問題，開始」）

### 3.1 階級與核心
- **階級＝節點數，核心算 1 個**：Lv.1＝只有核心；Lv.2～6＝一環 1～5 格（Lv.6 剛好成五芒星）；Lv.7～10＝二環 1～4 格；三環留給之後。
- **核心的元素階級決定上限**：初階 Lv.2、中階 Lv.4、高階 Lv.6、極階 Lv.8、神階 Lv.10。實際階級＝min(節點數, 核心上限)；超過上限的節點仍要扣元素但不增加階級（擺放時預測詞條要顯示「超過核心上限」）。
- 只有核心、沒有環時沒有符文：形態預設為「射」（設計者補充）。
- 起始魔法「魔力彈」（無屬性）保留為開局就會、不能從魔法陣合出的魔法；「魔力過載」（合成失敗時的懲罰魔法）的去留由規劃者決定是否還需要。

### 3.2 各環的元素門檻
- 一環要**初階以上**的元素、二環要**高階以上**（設計者決定；原本想的「一環中階、二環極階」會讓開局只有初階元素時連 Lv.2 都合不出來）。高階元素可以放進低階的環，但沒有額外加成。主要的階級門檻是核心（3.1）。
- 解鎖（有沒有格子）與元素（填不填得進去）是兩條獨立的限制。

### 3.3 合成的成本與結果
- 按下合成時扣掉核心與每個節點上的元素（放幾個扣幾個）；符文不扣（2.3）。
- **專案 2 只有兩種結果：一般成功、大失敗**。大失敗：扣掉元素、什麼也學不到。基本機率 **10%**，迴路對不上時調高（數值由規劃者提出、使用者確認）。非常成功、異變、熟練度在專案 3。
- 合成一律伺服器擲骰（AGENTS.md 第 6 節「伺服器是銀行」）。

### 3.4 五芒星與迴路
- 一環 5 格排在五芒星頂點。**圓周相鄰＝相生、星線相連＝相剋**。
- 相剋沿用 `combat-rules.ts`：水剋火、火剋風、風剋土、土剋雷、雷剋水。
- **相生循環：水 → 土 → 火 → 雷 → 風 → 水**（由相剋推出：五芒星上相生與相剋不能重疊，這是唯一不衝突的順序。對應：水潤澤大地、地底熔岩生火、火的熱氣生雷、雷暴捲起狂風、風帶來雨水）。
- **分支數**：每個節點有「朝內」「朝外」的分支數，**放下節點時就顯示**。規則以「元素個性＋所在環與位置」為主，加少量一次性的固定亂數（全世界相同）；例：雷傾向朝外分岔、土傾向單線。內圈節點朝外的分支數＝外圈節點朝內的分支數，且兩元素不相剋，才「對得上」。產生規則後要驗證**教科書上的名魔法都接得上**。
- **迴路的對接**（設計者決定）：**核心算內圈**，所以 Lv.2 起就有作用。相鄰兩層（核心↔一環、一環↔二環）對得上的條件：內層朝外的分支**總數**＝外層朝內的分支**總數**，而且連在一起的兩個元素不相剋（核心↔每個一環節點；一環節點↔與它相連的二環節點，連接方式由規劃者定義並寫進測試）。對不上時大失敗機率調高（3.3）。所有教科書名魔法都要接得上（寫成測試）。
- 節點之間弧線上的符文、花紋（總體設計 4.1）：專案 2 只做「每環一種符文」；弧線花紋留待之後。

### 3.5 陣 → 魔法的對應
- **形態**：符文 → `Effect['kind']`（2.7 的表）。
- **規模**：階級（節點數，受核心上限）→ 傷害與範圍，照 `TIER_STEP` 1.8 的強度曲線；**魔法陣合出的魔法也要守住每高一階約 ×1.8**，由 `tests/sim/tier-curve.test.ts` 把關（量測情境照舊）。
- **主屬性**：核心元素。**附加效果**：節點元素（火燃燒、風擊退、水潮濕、土緩速、雷連鎖），同種越多越強；相生加成、相剋削弱或反應（具體反應表由規劃者提出、使用者確認）。
- **名魔法的數值由同一套公式產生**（設計者決定）：名魔法＝「公式依陣算出的魔法＋名字與文案」，符合「世界的規律是共用的」。現有手調的參數（`pull`、`follow`、`haste`、擊退下修等）不再逐招保留；手感會變，強度曲線重新驗證。
- **魔法的屬性＝陣上出現的所有元素**（核心＋節點；設計者決定）：例如煉獄（火 火 風 火）是火＋風。影響相剋 ±10%、被動加成與星圖位置。
- **預測詞條**：擺放時即時顯示「主屬性、附加效果、大約階級」，例如「火・擴散・灼燒・約 Lv.6」；**形態不寫在詞條裡**，揭曉時才確定（玩家可從自己擺的符文猜）。

### 3.6 魔法的身分與存檔
- 魔法 id 由**標準化後的陣**決定（設計者決定）：
  - 核心元素、**實際階級**（不是核心元素的階級）、各環節點的**元素種類**（不看放的是幾階：3.2 已定高階放低環沒有加成）、形態；所有環的符文標準化為實際形態。
  - **旋轉或鏡像後相同的排法算同一個陣**（相生、相剋只看相鄰與星線）。實作要有一個唯一的標準寫法（例如取所有旋轉／鏡像中字串最小者）。
  - **超過核心上限的格子不能放**（介面直接停用，不扣元素），所以不會出現「多放卻沒用」的節點。
  - 同一個標準化陣只有一筆。
- 舊的兩輸入合成與自創 id `c(<a>|<b>)` 停用。
- 名魔法＝某個標準化陣有名字與文案；合出那個陣就學會那個名魔法。
- **存檔再重置一次**（新 migration），已學會的魔法用新格式記錄。

- 迷霧、`revealed`、「關鍵道具散開迷霧」移除；關鍵道具改成開放格子（2.6）。被動節點與解鎖條件保留。

### 3.8 畫面
- 合成台的位置換成牛皮紙（不重新設計整個主介面）。
- 擺放：**點選格子 → 選元素或符文**（手機也能用；拖曳是之後的加分項）。
- 合成：3 秒圓形進度條＋依陣上元素的特效；稀有（2.10）時 5 秒。
- 被伺服器拒絕時（材料不足等）不播完整動畫，陣保留並顯示原因（沿用合成台的行為）。

### 3.9 防作弊
- 合成、強化、使用關鍵道具、解鎖被動仍是伺服器動作；已學會的魔法、格子的開放、符文的取得都是**伺服器擁有**的欄位，上傳不能改（`audit.ts`）。
- `tests/sim` 各條路線 0 次被拒、worker 對抗測試全過，仍是必要條件。機器人要改成用魔法陣合成。

## 4. 不在這個專案（之後再決定或其他專案）
- 多形態的名魔法（2.5）。
- 大成功、異變、熟練度、符文「相加／增強／第三種形態」（專案 3）。
- 任務線、教科書（書與提示內容）、任務取得符文（專案 4）。
- 繪製符文要消耗素材或物品（2.3）。
- 三環、弧線上的花紋、拖曳擺放。
- 光、暗元素（待辦 0e）。

## 5. 驗收
1. 牛皮紙上可以擺核心、一環、二環、符文，隨時拆換；擺放時看得到分支數與預測詞條（主屬性、附加效果、大約階級），看不到形態。
2. 按下合成：3 秒圓形進度條與元素特效，跑滿揭曉；稀有時 5 秒。被拒絕時陣保留並說明原因。
3. 不同環放不同符文時，形態約各 50% 擇一（伺服器擲骰，有單元測試）。
4. 同一個標準化陣只有一筆魔法；魔導書顯示標準化後的陣。
5. 2.5 範例裡的名魔法都能用魔法陣合出（單一形態）；分支規則讓所有教科書名魔法接得上。
6. 格子照 2.6、符文照 2.7 開放；開局能合出 Lv.2。
7. 魔導書是五元素星域；點星可以看陣與數值、裝備、把陣擺到牛皮紙上。
8. 強化照舊；稀有魔法照 2.10 可以刷到，發現紀錄與揭曉動畫正常。
9. 強度曲線（`tier-curve`）照舊把關；`tests/sim` 0 次被拒；`npm test`、`npm run build` 通過。
