## 2. A：合成演出

### 2.1 結果與演出的對應

| 演出 | 觸發 | 備註 |
|---|---|---|
| **失敗** | 伺服器回 `failed`（大失敗） | |
| **成功** | `known`（已經會的魔法） | |
| **成功＋新魔法** | `learned` 且不是稀有 | 同一套演出加強一級，不另算一種 |
| **異變** | 稀有魔法（現在的 2%） | 魔法陣規格 3.9：專案 3 把這 2% 改成異變 |
| **大成功** | 這一輪沒有真正的觸發 | 先做好演出，用開發預覽觸發；專案 3 接上 |

稀有魔法揭曉後照舊接全螢幕 `RareReveal`。

### 2.2 蓄力（3 秒，四種結果相同）

前 3 秒四種結果完全一樣，看不出結果。伺服器回應即使提早到，也要等 3 秒跑完才揭曉；3 秒到了還沒回應，就停在「停頓」那一刻（粒子凝住、光球微微脈動）等回應，回應到了立刻揭曉。連線失敗或被拒絕時，光球淡掉、陣保留，沿用現在的錯誤訊息。

1. **0～60%：**
   - 陣線依序亮起（沿用）。
   - 符文帶加速（沿用）。
   - 粒子從紙的四周被吸向陣心。顏色用陣上的元素色，加上金色。
   - 整張紙慢慢變亮。
2. **60～90%：**
   - 粒子變多、變快。
   - 陣心出現光球並越來越大。
   - 紙小幅持續震動。
   - 進度環的光變強。
3. **最後約 0.3 秒：**
   - 停頓：粒子凝住、畫面微暗、震動停止。
   - 停頓之後進入揭曉。

### 2.3 揭曉

- **失敗：**
  - 光球爆成白閃，接著墨黑煙霧往上散。
  - 焦痕與斷線沿用。
  - 紙震 0.4 秒，灰燼粒子慢慢落下約 1.5 秒。
- **成功：**
  - 光球爆開，金色光柱（沿用）加上金色粒子往外噴一圈。
  - **新魔法**再加一圈元素色光環、粒子量加倍。
- **大成功：**
  - 白金雙層光柱。
  - 粒子像噴泉往上衝再落下。
  - 紙邊描一圈金光。
  - 紙放大到 1.05 倍再彈回。
  - 結果字樣是「大成功！」。
- **異變**（共 5 秒）：
  - 第 3 秒開始的揭曉會「反轉」：本來要爆開的光被吸回陣心，畫面變暗，紙上出現星空（沿用），陣心冒出紫色與元素色的裂紋。
  - 這段約 2 秒，最後星爆，接 `RareReveal`。
  - 換句話說，玩家在第 3 秒先以為要揭曉了，接著才發現是異變。

蓄力時間沿用 `PROGRESS_MS` 3000 與 `RARE_PROGRESS_MS` 5000。現在一知道是稀有就把整段改成 5 秒、把稀有的樣子提早顯示出來；這一輪改成前 3 秒照一般蓄力，最後 2 秒才是異變段。

### 2.4 Pixi 粒子層

- 新增 `src/render/circle-fx.ts`，提供 `CircleFx` 類別。
  - 在 `.parchment-sheet` 上疊一張透明畫布，`pointer-events: none`。
  - 方法：`charge(colours, ms)`、`reveal(kind)`、`stop()`、`destroy()`。
  - `kind` 是 `'fail' | 'success' | 'learned' | 'great' | 'mutation'`。
- **只在演出期間跑。** 第一次合成時才建立；閒置時停止 ticker，不吃效能。
- **粒子上限 400（佔位）**，和戰鬥畫面的 `MAX_ACTIVE_FX` 分開算。
- **初始化失敗（例如沒有 WebGL）不報錯**，只剩 CSS 的部分。
- 紙張本身的狀態（焦痕、震動、變暗、光柱、星空）照舊用 CSS 與 SVG。
- 測試用 jsdom 時 mock `CircleFx`，只驗證 `CircleTable` 在正確時間呼叫正確的 `kind`。

### 2.5 開發預覽

開發模式（`import.meta.env.DEV`）下，網址加 `?fx` 時，牛皮紙旁會出現 5 個按鈕：失敗、成功、新魔法、大成功、異變。按下就在目前的陣上播放蓄力加揭曉，不送伺服器、不扣材料。正式 build 不會出現這些按鈕。

## 4. C、D：羊皮紙版面

### 4.1 合成按鈕在紙上（C）

- 「合成」按鈕放在羊皮紙內、魔法陣下方、下方捲軸上面的空白處，水平置中，不能和陣重疊。
  - 陣寬 76%，置中，上下各留紙高約 19.6%。
- 按鈕做成蠟封或金色印章的樣子，高度至少 44 px。
- 不能合成的原因文字（例如「先選核心元素」）用小字放在按鈕下方，也在紙上。
- 「清空魔法陣」維持在紙下面。

### 4.2 紙的左右（D）

- **左邊：預測。** 內容就是現在的 `predictionOf`（主屬性、附加效果、大約階級），再加大失敗機率與迴路是否對得上；迴路不合的警告也搬到這裡。
- **右邊：這次會消耗的元素。** 每個節點與核心的元素、階級、需要的數量和持有量，不夠的標紅。
- 兩張都做成桌上的小紙條（便條紙樣式），不蓋到羊皮紙。
- **寬度不夠就放回紙下面：** 右欄寬度要至少等於紙寬加左右各 150 px（佔位）才放在兩側，否則照現在的排法依序放在紙下面。手機一定放在紙下面。

## 5. E：離線收益的通關時間

### 5.1 離開時停錶

- 新增伺服器擁有的欄位 `pausedMs`（距上次通關以來離開了多久），在 `persist.ts` 給預設值 0，不需要 migration。
  - `audit.ts` 拒絕用戶端改動這個欄位，比照 `awayAt`、`offlineUntil`。
- **`claimOffline` 每次結算（不論有沒有收益）都要累加：**
  - `pausedMs += now − max(離開的起點, lastClearAt)`。
  - 離開的起點：`awayAt > 0` 時用 `awayAt`，整個關掉遊戲時用 `prevSavedAt`；再和 `offlineUntil` 取較大的值，和現在算收益的起點相同。
- **通關結算時：**
  - 通關時間 ＝ `now − lastClearAt − pausedMs`，下限仍是 `minStageMs`。
  - 記錄後 `pausedMs` 歸零。
- **原本的「不記時間」條件拿掉：** `awayAt > 0` 與 `offlineUntil > lastClearAt` 這兩條，因為離開的時間已經扣掉。魔王關、`lastClearAt <= 0` 照舊不記。
- **如果通關時 `awayAt > 0`（理論上戰鬥凍結時不會通關）**，先把 `now − awayAt` 也算進離開時間再扣。

### 5.2 沒有紀錄時用預設時間

- 最遠已通過的那一關沒有任何通關時間時，`claimOffline` 改用預設值 `minStageMs(zone, stage) × CLEAR_TIME_FALLBACK`，`CLEAR_TIME_FALLBACK` 佔位 2。
- 預設值比實際通關慢，所以只會少給、不會多給。

### 5.3 沒有收益時說原因

`OfflineResult` 的 `none` 加上 `reason`：

| `reason` | 意思 | 卡片顯示（只有這種情況才顯示卡片） |
|---|---|---|
| `notCleared` | 還沒有通過任何小怪關 | 「還沒有通過任何關卡，離線時沒有收穫。」 |
| `cannotDamage` | 裝備中的魔法打不動那個地點 | 「裝備中的魔法打不動〈地點〉，離線時沒有收穫。」 |
| `tooShort` | 不到一個 tick（30 秒） | 不顯示卡片 |

**已經測出來的情況（可以寫成重現測試）：** `ron` 帳號 `clearedStages` 是 `{"mist_meadow":3}`、`clearTimes` 是 `{}`，結算回 `none`。改完要有收益（用預設值）。

## 6. F、G：符文

### 6.1 符文圖示（F）

- 8 種符文各有一個圖示：射、刃、波、鏈、域、墜、嵐、臨。
- **選用美術：** `public/assets/rune-<id>.webp`（例如 `rune-bolt.webp`），透明背景，深墨色線條，約 256×256。
  - 提示詞寫進 `docs/art-assets.md`。
  - 用 `useArt` 預載，載入成功才用圖。
- **暫代：** 沒有圖時用程式畫的簡單 SVG 圖形，取代現在的中文字。
  - 射：箭頭。刃：交叉兩刃。波：同心弧。鏈：兩個相扣的環。
  - 域：圓內方格。墜：向下的流星。嵐：漩渦。臨：倒三角加中心點。
- **符文帶：** 從沿著圓重複寫中文字，改成沿著圓等距重複排同一個圖示（每環約 12 個，佔位），中間用短的古文字線紋連起來。
- 符文帶在合成時加速旋轉，沿用。
- 符文圈（點符文帶後長出的 8 個選項）也用圖示，下面小字寫中文名稱。
- 無障礙：aria-label 仍是中文名稱。

### 6.2 未取得的符文顯示「？」（G）

- 符文圈裡沒取得的符文，圖示與名稱都換成「？」，維持停用。
- aria-label 改成「未取得的符文」。
- 底下的說明照舊：「未取得的符文從魔王取得」。
- 符文帶上不會出現沒取得的符文（帶子只畫目前選的那個），不受影響。

- **位置：**
  - 從戰鬥長帶右上角移到長帶上方正中間。
  - 手機也是置中，放在長帶上方。
  - 不能蓋住關卡進度條、DPS、魔王倒數、牛皮紙的預測。
- **按鈕：** 「裝備」按鈕高度至少 44 px，通知文字放大到 15 px（佔位）。
- **倒數條：**
