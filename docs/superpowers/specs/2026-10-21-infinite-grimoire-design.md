## 1. 意圖與核心體驗

一款極簡像素風的網頁放置遊戲。畫面正中間的小人**自動**用魔法攻擊魔物，玩家不操作戰鬥，而是專心**合成魔法**與**煉金**。換上新魔法時，效果立刻在戰鬥畫面上看得到（射線、連鎖、麻痺……）。

**玩家離開遊戲時，腦中應該在想：「下一步要怎麼合成，才能拿到更強的魔法？」** 這是整個設計的北極星，所有取捨以它為準。

核心循環：

```
自動戰鬥 → 擊敗魔物 → 掉落元素／素材
   ↑                          │
   │                          ├─→ 合成：學會新魔法 → 裝備 → 打得更強 → 前往更高等級地點
   │                          └─→ 煉金：產物出售換金幣，或自用取得增益
   └────── 商店用金幣購買元素／素材 ←──┘
```

## 2. 目標、非目標、反目標

**目標**
- 換魔法是看得見、摸得到的爽感：每個魔法在戰鬥中都有清楚可辨的表現。
- 「怎麼合出更強的魔法」持續成為玩家的好奇心來源：機率變異、殘卷線索、隱藏節點。
- 支持專精路線（例如純火系大魔導士）與混合路線，兩者都可以走到底。
- 遊戲可以玩 1～3 小時以上的漸進探索，並支援離線收益。
- 輕度的社群互動：看到別人發現的稀有魔法、各屬性的排行與至尊稱號，以及之後的玩家市集。
- 擋下明顯的作弊，讓稀有發現和至尊稱號有意義。

**非目標（目前不做）**
- 玩家手動操作戰鬥。
- 斷線遊玩：遊戲**必須聯網**。
- 收集或儲存玩家的 email。
- 玩家之間的直接交易、聊天、媒合。
- 付費、課金、廣告。

**反目標（即使功能正常也算失敗）**
- 某條專精路線因為內容設計被卡住，例如火系玩家必須打水系魔物才能拿到關鍵素材，或必須學其他屬性的魔法才能過關。
- 屬性相剋太強，讓「換成剋制屬性」變成唯一解，削弱專精路線。
- 換魔法只是改數字，戰鬥畫面上看不出差別。
- 轉生讓玩家覺得過去全部白玩。

## 3. 限制

- **平台**：網頁遊戲，手機與桌面自適應，部署在 **Cloudflare**。之後的網域也在 Cloudflare 購買。原始碼放在 GitHub repo：`Ronaldzzzzz/InfiniteGrimoire`。
- **必須聯網**：遊戲開始前和遊玩過程中都需要連線到伺服器。
- **存檔**：存在伺服器上，伺服器是唯一可信的來源（見 4.12）。瀏覽器只保存登入用的權杖（token）。
- **隱私**：不儲存 email。Google 綁定只存 Google 提供的使用者編號；密碼只存雜湊值。
- **美術**：第一版只用點、線、面、方塊和粒子特效，不使用貼圖。之後由使用者用其他 AI 工具補齊貼圖（見第 9 節）。
- **視覺基調**：1-bit／Pico-8 復古低像素風，深色夜空背景，搭配符文綠和琥珀金。介面像古老但整潔的魔導書或煉金工作台，不放多餘裝飾。
- **語言**：介面以繁體中文為主。資料結構保留英文名稱欄位，方便日後做多語系。

## 4. 完整遊戲系統

### 4.1 戰鬥

- 全自動。小人站在畫面中央，**沒有血條，永遠不會死**。
- 畫面上同時有多隻魔物，連鎖、範圍類魔法才有意義。魔物被擊倒後重生。
- **階級與防禦門檻**（擋住玩家的機制）：階級共 **20 階**。魔物有**階級**和**防禦值**，魔法有**階級**和**攻擊力**。設魔物為 M 階，滿足下列**任一**條件時，魔法才會造成傷害，否則傷害為 0：
  - 魔法階級 ≥ M − 1，也就是最多低一階；
  - 魔法階級更低，但攻擊力 ≥ 魔物防禦值的 70%，也就是能突破防禦。

  例子：打 10 階魔物，要用至少 9 階的魔法，或是 9 階以下但能突破防禦的魔法。所以用弱魔法是真的打不動，不是只有打得比較慢。滿足條件後的傷害公式【交給開發者】。
- **魔王與區域解鎖**：每個區域有魔王，擊敗後開啟新的區域。
- **越級效益遞減**：魔法階級 ≥ M + 2 時觸發，例如用 12 階魔法打 10 階魔物。掉落效益會下降，推動玩家往更高等級的區域走。不鼓勵玩家留在太簡單的地方掛著，但也不會阻止。可以考慮再加適度的懲罰。遞減採**指數遞減**：階級差距越大，遞減越多，降到約 **50%** 後就不再減少。
  - **【我的決定】** 參考公式：設差距 d = 魔法階級 − M，當 d ≥ 2 時，效益 = 50% + 50% × kᵈ⁻¹。
  - 預設 k = 0.5，所以 d = 2 時是 75%，d = 3 時是 62.5%，d = 4 時約 56%，之後越來越接近 50%。
  - k 值【交給開發者】調整。
- **【我的決定】** 元素的初階、中階、高階等分級，和魔法的 1～20 階是兩套系統。哪個魔法階級需要哪一級的元素，【交給開發者】在資料裡定義。
- 魔法可以帶狀態效果，例如麻痺、灼燒、冰凍、擊退。
- **屬性相剋存在，但壓制幅度最多 10%**（傷害加成或減免都算在內）。
- 小人一開始只有 **1 個魔法欄位**，之後透過天賦或道具擴充。
- **【我的決定】** 初始魔法是無屬性的「魔力彈」。所有地點都會掉五屬元素，只是比例不同，玩家不會被初始狀態導向單一屬性。

### 4.2 元素與素材

- **五種基礎屬性**：風、火、雷、土、水。所有魔法都從這五種出發。
- **特殊屬性**：光、暗，只能透過機率變異取得（見 4.4、4.6）。
- 元素分階：初階、中階、高階，之後可再擴充。
- 元素升階：低階元素可以合成高階，**【我的決定】** 預設三個低階換一個高一階，數值交給開發者調整。
- **無屬性元素素材**：轉生時退還的通用素材（見 4.7）。
- 魔物會掉落元素與素材（如「雷獸角」）。**重要素材不能只從單一屬性的魔物或地點取得**：至少要有另一條取得途徑，例如商店、煉金，或其他屬性的地點。

### 4.3 合成（學魔法）

- 玩家把元素或素材放進合成槽進行嬗變。
- 魔法有**前置條件**。例如閃電術需要已習得雷電術，再用兩個中階雷元素合成。
- **結果走機率**。同一組合可能有多種結果，例如閃電術 92%、雷暴 7%，另有極小機率產出光暗系變異。
- **不成立的組合**：第一次嘗試**不會被拒絕**，會消耗部分材料，並記錄為「無反應」。之後再放入同一組合時，直接提示「無反應」，不再消耗。**【我的決定】** 消耗比例【交給開發者】。
- **【我的決定】** 前置條件未滿足的魔法，不會出現在結果表裡；只有前置條件已滿足的魔法才會被抽到。
- **【我的決定】** 抽到已經學會的魔法時，退還一部分元素。
- 系統會記錄**已嘗試過的組合**，並顯示**玩家自己實際抽到的頻率**，不顯示真實機率，以保留探索感。這呼應原 README 的「動態顯示歷史出貨機率」。
- **【我的決定】** 合成槽一開始有 2 格，之後可以擴充。
- **殘卷線索**：不提供完整配方手冊。魔導書只顯示模糊提示，例如「當雷鳴與烈焰交會……」。
- 學會的魔法**永久**記在魔導書裡。施放魔法不消耗元素，元素只在合成時消耗。

### 4.4 魔導書（技能樹）

**五屬魔導書**：發散型技能樹，以中心向外輻射，切成五個扇形區塊，每個屬性一塊。

- 由內到外依序是：初階 → 中階 → 高階魔法 → 稱號節點。
- **相鄰屬性混合**（外圈五角形的邊）：在相鄰兩區塊的交界放混合魔法節點，例如火加風是火焰旋風、水加火是蒸氣爆發。兩邊的前置都學會才能合成。手感上門檻較低、成功率穩定。
- **不相鄰屬性混合**（中央五芒星）：五個初階節點是五芒星的五個頂點。每條星線連接兩個不相鄰屬性，線的中點是該組的混合魔法，例如火加雷是爆雷、風加土是沙暴。手感上是相悖的力量硬湊在一起：需要兩邊的**高階**前置，成功率低、變異機率高，也是最容易變出光暗的地方。
- 五芒星區域一開始被封印或霧蓋住。玩家在兩個不相鄰屬性都達到高階後，對應的星線才解封，並播放解封動畫。
- 節點位置從一開始就固定，之後不重新排版。介面支援縮放和拖曳。
- 屬性在圓上的排列順序決定哪些組合算相鄰。**【我的決定】** 預設順序是火、風、雷、土、水，開發者可以調整。

草圖參考：`.superpowers/brainstorm/` 內的 `grimoire-v3-pentagram.html`（不在 git 中，僅供本機參考）。

**稱號**
- 技能樹包含**魔法節點**和**被動節點**，例如攻擊 +2%。被動節點最多只能佔全部節點的 **20～30%**，其餘都是魔法。
- 區塊內**已啟動的節點數量**達到門檻（例如 50 個）時，自動啟動該屬性的稱號，並給小人加成。所以完整版每個屬性區塊至少要有 50 個以上的節點，其中約 35 個以上是魔法。資料結構從第一版就要支援這個規模。
- 部分稱號有限制條件。例如「火屬性大魔導士」的條件之一是**不可學習其他屬性的魔法**。

**光暗魔導書**
- 獨立的一本魔導書，**左光右暗**，中間是硬分界，沒有模糊或混合地帶。
- 一開始只開放少量見習節點，其餘封印。
- 達成條件後，玩家可以在兩本魔導書之間切換。
- 達成條件並**捨棄五屬魔導書**後，正式轉職為光或暗魔導士，解放完整的光暗魔導書。
- **待定**（第一版不做，之後再決定）：轉職條件；捨棄時是否退還資源；轉職後能不能回頭；切換魔導書時，另一本已學會的魔法能不能裝備；轉生會不會清掉光暗魔導書；「煉金技術」和「煉金熟練度」的差別。**【我的決定】** 存檔格式從第一版就加上版本號，方便之後擴充。

### 4.5 煉金

- 把素材煉成產物。產物可以**出售**換金幣，或**自用**取得增益：
  - **暫時增益**：類似藥水，持續一段時間，例如火屬性攻擊 +10%，可以拿來衝更高等級的地點。
  - **永久增益**：稀有。同類效果有疊加上限，避免數值失控。
- 結果走機率，產物分普通、優良、極品等品質，品質越高增益越強。
- **熟練度**：以配方為單位累積。熟練度越高，**成功率、品質和異變機率都會提高**。

### 4.6 商店與經濟

- 用金幣購買元素和素材。
- 貨架隨地圖進度解鎖更高階的商品。
- 價格比自己打或自己煉來得高，是給不想等的玩家的捷徑，不是主要來源。
- 金幣只來自打怪和出售煉金產物。

### 4.7 轉生

- 在魔導書中觸發。效果是忘記所有魔法，並把投入的資源以 **85%** 退還成**無屬性元素素材**，讓玩家重新選擇職業方向，例如從火系改走水系。
- **保留**：永久增益、煉金熟練度與煉金技術。

### 4.8 地圖

- 多個地點，每個地點有等級，等級越高怪越強、掉落越高階。
- 每個地點有主要屬性，例如雷鳴峽谷多雷系魔物，但要遵守 4.2 的「重要素材不限單一屬性」原則。

### 4.9 離線收益

- 「離線」指玩家沒有開著遊戲的時間，不是斷線遊玩。玩家關掉遊戲期間，小人視為繼續戰鬥，回來時領取掉落。
- 有時數上限，而且離線越久效率越低。**【交給開發者】** 實際上限和衰減曲線由開發者決定，草圖裡暫用 8 小時。
- 離線收益由**伺服器**依據上次存檔的時間和狀態計算並發放。

### 4.10 社群分享（願景，非第一版）

- 「禁忌配方卡」：玩家合出稀有魔法時，可以匯出一張卡片圖，內容包含配方、機率和玩家代號，方便分享到 Threads、X、Discord。

### 4.11 帳號

- 第一次打開遊戲時，自動建立**匿名遊客帳號**，玩家只需要取一個顯示名稱。
- 之後可以綁定下列任一方式，以免換裝置或清掉瀏覽器資料時進度不見：
  - **帳號＋密碼**：帳號是玩家自訂的名稱，不是 email。密碼用 argon2 或 bcrypt 這類演算法雜湊後才儲存。
  - **Google**：只儲存 Google 提供的使用者編號（`sub`），**不儲存 email**。
- 不收集 email 是刻意的決定，避免任何「使用玩家 email」的疑慮。目前也不寄信。

### 4.12 伺服器與防作弊

- **伺服器當銀行**：玩家的進度和資料都存在伺服器上，伺服器上的存檔才是可信的版本。
- **戰鬥在瀏覽器中執行**，定期把新存檔上傳到伺服器。伺服器保留**上一份已接受的存檔**，新存檔進來時，用**伺服器自己的時間戳**比對兩份存檔之間的時間差和進度差：
  - 用快速結算函式算出「這段時間內、用這些魔法、在已解鎖的地點，最多可能拿到多少」。進度超過這個上限，再加上容許誤差，就拒絕這份存檔，退回舊存檔。
  - 只能由伺服器改變的資料，例如已學會的魔法，上傳時不得被改動。
- **合成由伺服器擲骰**：玩家按下「合成」時，請求送到伺服器，由伺服器擲骰、記錄並回傳結果。稀有魔法的發現和至尊稱號都依賴這個結果。
- **上傳時機**：每隔一段時間（例如 30 秒）、合成時，以及關閉頁面時。
- **可疑帳號**：被拒絕的存檔都會記錄。同一個帳號反覆被拒絕時，標記為可疑，暫停他上排行榜和取得至尊稱號的資格，但不直接封鎖。
- 遊戲邏輯是同一份 TypeScript 程式碼，瀏覽器和伺服器共用，不寫兩套規則。

### 4.13 稀有魔法發現紀錄

- 公開顯示**魔法名稱和發現者**。配方只顯示模糊線索，也就是該魔法的殘卷提示。**遊戲內不會公布配方。**
- 只有**稀有魔法**會上發現紀錄：在結果表裡機率低（例如 10% 以下）的變異結果，以及之後的光暗魔法。
- 第一個發現某魔法的玩家，會被永久記錄為「**首位發現者**」；之後的發現者只出現在最近發現的動態裡。
- 玩家在遊戲外自行分享配方，不阻止。

### 4.14 排行與至尊稱號

- 每個屬性都有一般排行榜，即時顯示前幾名，讓玩家知道自己離至尊還差多遠。
- **至尊稱號**：五個屬性各一位，例如「至尊火魔導士」。光暗之後再加。
  - **結算時間**：每天伺服器時間跨日時結算一次，以台灣時間（UTC+8）午夜為準。
  - **資格**：已經取得該屬性的大魔導士稱號，所以也必須遵守「不學其他屬性魔法」的限制。可疑帳號不參加結算。
  - **比較方式**：先比該屬性區塊已啟動的節點數；相同時比打倒的最高魔王階級；兩者都一樣時，先達到的人勝出。
  - **持有期間**：結算後到下一次結算前，這個位子不會變動；隔天可能被搶走。
  - **效果**：主要是榮譽。名字旁有特殊標記，並在發現紀錄和市集上顯示，另外附一點小加成，不會強到讓第一名永遠守住位子。

### 4.15 玩家市集

- 玩家 A 賣出物品時，賣給系統，當下就拿到金幣。伺服器同時記錄一筆「A 上架了 X」。
- 其他玩家進入市集時，伺服器從這些紀錄裡**隨機抓 n 筆**別人賣出的物品來顯示，不會出現自己賣的東西。
- 同一筆紀錄可能同時出現在 B、C 等多位玩家的市集裡，**每個人都可以買，互不影響**；買到的是系統生成的複製品。**【我的決定】** 每位玩家對同一筆紀錄只能買一次。
- 紀錄超過時限後自動清除。
- **市集售價必須高於商店價格**，差額會從經濟裡收回金幣，避免通膨。
- **只有部分物品能上市集**，由物品資料中的欄位標記。市集的價值在於買到商店不賣、或自己的進度還沒解鎖的物品，也讓專精玩家取得自己地點不太會掉的素材。
- 不做配對媒合，也不讓玩家直接互相交易。
- **【我的決定】** 玩家可以付少量金幣刷新市集，重新抽 n 筆。

## 5. 技術選擇【我的決定】

- **TypeScript + Vite**。
- **Pixi.js**：戰鬥畫面，包含粒子、射線、連鎖等即時特效。
- **React**：介面分頁，包含合成、煉金、商店、魔導書。
- **SVG**：魔導書技能樹，方便縮放和拖曳。
- **遊戲邏輯**：獨立的純 TypeScript 模組，不依賴畫面，包含戰鬥數值、機率、合成、熟練度和離線收益，必須可以用 **Vitest** 測試。可以用固定亂數種子重現結果，也能直接模擬「離線 N 小時拿到多少」。
- **資料驅動**：元素、魔法、配方、魔物、地點都寫在 JSON 資料檔裡，載入時做格式檢查。新增內容只改資料、不改程式。
- **Cloudflare Workers**：同一個 Worker 同時提供靜態網頁和 `/api/*` 後端，用 **Hono** 處理路由。
- **Cloudflare D1**：資料庫，存放帳號、存檔、合成紀錄，以及之後的發現紀錄、排行和市集。
- **Cron Triggers**：每日的至尊稱號結算。結算是每天一次的批次作業，所以不需要 Durable Objects。
- 伺服器直接 import 共用的遊戲邏輯模組。
- **部署**：使用 `wrangler`。網域之後在 Cloudflare Registrar 購買並綁定。

## 6. 第一版範圍（MVP）：自動戰鬥 + 合成換魔法

**第一版的目的**：驗證「看著小人打怪 → 合出新魔法 → 馬上看到變強、變好看 → 想要下一個魔法」這個循環好玩。

**包含**
- 自動戰鬥：小人、多隻魔物、魔物重生、魔法施放、傷害數字、狀態效果。
- 階級與防禦門檻、每個地點一隻魔王、擊敗魔王解鎖下一個地點、越級效益遞減。第一版只用到 20 階中的前幾階。
- 不會出現光暗變異。
- 掉落：五屬元素的初階和中階，以及少量素材。
- 元素升階：低階換高階。
- 合成：合成槽、前置條件、機率結果、已嘗試紀錄、殘卷線索。
- 五屬魔導書的簡化版：可檢視已學會和未學會的節點。
- 內容份量：每個屬性 2～3 個魔法，加 1～2 個相鄰混合魔法。
- 地圖：2～3 個地點。至少有一個地點用初始魔法打不動，用來驗證推動玩家找更強魔法的力量。
- 1 個魔法欄位，換魔法時即時切換。
- 所有視覺效果都用點線面、方塊和粒子呈現。
- **伺服器核心**：
  - 匿名遊客帳號，需要顯示名稱。
  - 存檔上傳到伺服器，並做進度合理性檢查；被拒絕時退回舊存檔，並記錄拒絕次數與可疑標記。
  - 由伺服器擲骰的合成。
  - 必須聯網：沒有連線時顯示提示畫面，連線恢復後繼續。
  - 部署到 Cloudflare。

**不包含（保留在完整設計中）**
- 第二版：綁定帳號密碼和 Google、稀有魔法發現紀錄、排行榜、至尊稱號與每日結算。
- 第三版：煉金、熟練度、商店、金幣、玩家市集。
- 之後：稱號、轉生、光暗魔導書、五芒星的不相鄰混合、離線收益、禁忌配方卡、天賦系統、多個魔法欄位。**【我的決定】** 這些項目之間的先後順序之後再排。

**完成標準**
- 新玩家在 5 分鐘內，能自己理解「打怪 → 拿元素 → 合成 → 換魔法」。
- 每個魔法在戰鬥畫面上都能一眼分辨。
- 打不動的地點會讓玩家主動回頭研究合成。
- 遊戲邏輯有自動化測試，包含機率、前置條件、防禦門檻和戰鬥數值。
- **【我的決定】** 有模擬測試證明：五條單一屬性路線都能各自打通第一版的所有地點和魔王，專精路線不會被卡住。
- 正常遊玩上傳的存檔不會被誤判拒絕：模擬測試中，五條路線的機器人每 30 秒上傳一次，全部都被接受。
- 竄改過的存檔會被拒絕，例如背包數量暴增、自己加上魔法、或短時間內打倒魔王。
