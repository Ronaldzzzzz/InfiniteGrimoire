# 專案 1：橫向戰鬥帶與關卡（設計規格，2026-10-29）

上層文件：`docs/superpowers/specs/2026-10-29-magic-research-rework-design.md`（第 4.5 節、第 5 節順序 1）。本專案只換戰場與推圖方式，**合成、魔導書、魔法內容都維持現狀**（專案 2 才換成魔法陣）。

## 1. 目的

把圓形戰場換成主介面下方的一條橫向長帶，推圖改成一關一關的關卡，讓畫面主體留給之後的魔法研究。使用者：「小人一直往右走，遇到怪停下來自動施法」「邊研究魔法的同時小人會在下方移動並推圖，不佔空間也達到目的」。

## 2. 已拍板（使用者）

- 小人一直往右走，遇到怪停下來自動施法；沒有血量、不會死，強弱只影響通關時間。
- 關卡兩種：**小怪關**（無時間限制）、**魔王關**（最後一波是魔王，**限制 180 秒、遇到魔王波才開始倒數**，時間到判定失敗）。
- **波數不固定**：每關幾波、每波幾隻由關卡資料決定，後續關卡設計再定（之後可能有數十、上百波）。
- **結算戰利品**：打怪照常掉落；打完一關結算時**再給一次戰利品，約為這關掉落物的兩倍**，鼓勵越快推完越好（使用者：「鼓勵玩家越快推完圖領取結算」）。
- **進度用進度條呈現**，不直接顯示「第幾／幾波」。
- **離線收益**：畫面沒有被注目時，30 秒後開始計算；細節之後再討論（第 3.8 節）。
- 打完最後一波結算，之後往下一關或重新進入同一關；**自動前進或重刷由玩家勾選**。
- **魔王關要玩家按「進入」**；自動前進會停在魔王關前。
- **失敗退回前一關**。
- **波次要多**：主場階級魔法（不越級硬打）一個小怪關約 **2～3 分鐘**。
- 存檔重置（沒有真實玩家）。
- 傷害平衡與關卡細節之後再細磨；本專案只校準到「可以玩、符合上面的時間」。

## 3. 設計者決定（可在審閱時推翻）

### 3.1 畫面

- 桌面：遊戲主介面下方一條長帶，高度約 180 px，寬度與主介面同寬。小人站在左側約 1/4 處；怪從右緣進場往左走。
- 手機（寬 ≤ 600 px）：長帶固定在視窗底部（約 140 px），上方內容可捲動，不能被長帶擋住（底部留白）。
- 走路以背景與地面捲動表現（小人原地踏步）。
- 長帶左上：地點名稱與「關卡 3-4」，下方一條**關卡進度條**（已清的怪數 ÷ 這關總怪數；不顯示波數）；魔王波出現後顯示倒數（剩餘秒數）。DPS 讀數（`DpsMeter`）保留在長帶內。
- 長帶右上：「自動前進」勾選（記在 `localStorage`，不進存檔）；停在魔王關前時顯示「進入魔王關」按鈕；失敗時顯示「時間到，退回 3-9」幾秒。
- 現有的「魔王出現還差 N 隻」（`BossCounter`）移除，由關卡／波次指示取代；關鍵道具按鈕（`KeyItemBar`）、學會新魔法通知（`EquipToasts`）移到長帶旁或主介面上方，不能蓋住長帶的關卡資訊。
- 主介面其餘區域（元素表、合成台、魔導書）的排列在本專案只做讓位，不重新設計。

### 3.2 戰場幾何

- 引擎座標改成橫向：`x` 0（左緣）～ 1（右緣），`y` 是長帶內的上下位置（0～1，只做錯開與範圍判定，不是縱深）。小人固定在 `x ≈ 0.25`。
- **射程**：小人前方 `x` 在 `[0.25, 0.25 + RANGE]` 內有活著的怪就停下施法；沒有就前進。目標選擇（最近、最密、隨機、最強）只看射程內的怪。
- **停止線**：怪走到小人前方一小段距離就停下（取代 `STOP_R`），不會穿過小人。
- **擊退**：一律往右，不能把怪推出右緣（取代 `KNOCK_MAX_R`）。
- 移除圓形專屬的 `ENGAGE_R`、`KNOCK_MAX_R`、`walkedTouch`／碰線量測。

### 3.3 現有效果的對應（10 種 `Effect['kind']`）

| 效果 | 橫向的做法 |
|---|---|
| `bolt` 單發、`chain` 連鎖、`meteor` 隕石 | 不變，只換座標與目標範圍 |
| `ring` 環狀衝擊 | 以小人為中心往前擴散的半圓；`push` 往右 |
| `blades` 飛刃 | 往前方扇形飛出 |
| `zone` 地面區域 | 地上的一段區域；`pull` 往區域中心聚攏；`follow` 跟著目標 |
| `storm` 全場、`field` 延遲全場 | 涵蓋整條長帶 |
| `haste` 加速、`backfire` 反噬 | 不變 |

形狀參數（`radius`、`range` 等）的數值以「橫向長帶上看起來合理、清怪時間符合第 2 節」重新校準；強度曲線（每高一階約 ×1.8）照舊由 `tests/sim/tier-curve.test.ts` 把關，量測情境改成橫向關卡。

### 3.4 關卡結構

- 現有六個地點保留，每個地點 **10 關**：第 1～9 關小怪關、第 10 關魔王關（地點 1 是 1-1～1-10）。
- 每關的波次寫在關卡資料裡（波數、每波隻數、魔物表），**數量不固定**；本專案先放一組讓主場階級約 2～3 分鐘的起始資料，正式的關卡設計之後再做。**一波清完才出下一波**，兩波之間小人往前走一小段。
- 魔王關：前面是小怪波，最後一波是魔王；**倒數 180 秒從魔王波出現才開始**。
- 打倒魔王：照現在規則，第一次一定掉關鍵道具（R8、R13）、開放下一個地點的第 1 關。
- 已通過的關可以重新進入（刷素材）；地點選擇器改成「地點＋關卡」。
- 掉落：每次擊殺擲骰、立刻進背包（跟現在一樣）。中途離開或換關，已拿到的保留、這關不算通過、也沒有結算戰利品。
- **結算戰利品**：通過一關時，另外給一份約為「這關期望掉落 × 2」的戰利品（由這關魔物的掉落表算期望值，伺服器擲骰）。結算畫面列出這關打怪拿到的與結算戰利品。重刷已通過的關也有結算戰利品。

### 3.5 存檔

- `GameState`：`currentZone` 保留，新增 `currentStage`（1～10）與每個地點已通過的最高關卡（取代 `zoneKills`）；舊存檔一律重置（新 migration）。
- 關卡進度屬於戰鬥結果，跟擊殺一樣由用戶端上傳、伺服器檢查。
- **結算戰利品是伺服器動作**（例如 `POST /api/stage-clear`）：伺服器檢查這關的通過合理（經過時間 ≥ 這關最短時間、擊殺數相符），再擲骰並寫入；用戶端不能自己加結算戰利品（否則會超出 `audit.ts` 的掉落上限）。重複送同一次通過不會重複給。

### 3.6 防作弊（`audit.ts`）

- 擊殺上限改成依關卡算：每關的魔物總數固定，加上「兩波之間的最短時間」與「每波出現的最短時間」，得到每毫秒最多能殺幾隻（取代依 `spawnIntervalMs`／`pack` 估的 `maxKills`）；掉落上限照舊＝擊殺上限 × 單隻最大掉落。
- 關卡進度：一段時間內最多能前進幾關＝經過時間 ÷ 每關最短時間；魔王關的通過要有對應的魔王擊殺（關鍵道具規則不變）。
- `tests/sim` 各路線 0 次被拒、worker 對抗測試全過，仍是必要條件。

### 3.8 離線收益（範圍內，細節待討論）

- 觸發：畫面沒有被注目（分頁隱藏或視窗失去焦點）**30 秒後開始計算**。
- 收益的算法（照什麼速度、上限多久、是否含結算戰利品）、回來時的提示、與防作弊的關係，**這個任務開始前要先和使用者討論**；設計者預設由伺服器依經過時間計算，不信任用戶端。
- 計畫裡把它排成最後一個任務，前面的任務不依賴它。

### 3.7 模擬與測試

- `tests/sim/bot.ts` 改走關卡：自動前進、遇魔王關時判斷能否在 180 秒內打倒（打不倒就留在前一關刷）。
- `crowd.test.ts`（場上隻數）改成**關卡時間**的把關：主場階級每個小怪關 2～3 分鐘（中位數）；高一階明顯更快；低一階更慢。魔王：主場階級在 180 秒內打倒。
- 通關時間（`pure-paths`）與刷稀有（`rare-cost`）維持只印報告。
- `scripts/measure-dps.ts`、`tests/sim/measure.ts` 換成橫向情境。

## 4. 驗收

1. 桌面 1280×900、手機 390×844：長帶在下方、不擋其他介面、無橫向捲動。
2. 小人往右走、遇怪停下施法；怪不會穿過小人；擊退不出右緣。
3. 10 種效果在長帶上看得出各自的形狀。
4. 小怪關打完最後一波出現結算（含約兩倍的結算戰利品），自動前進開／關各自正確；進度條隨擊殺前進。
5. 自動前進停在魔王關前；按「進入魔王關」才開始；魔王波出現才倒數 180 秒；時間到退回前一關；打倒魔王掉關鍵道具、開放下一個地點。
6. 已通過的關可以重新進入；地點＋關卡選擇正常。
7. 主場階級小怪關 2～3 分鐘（模擬中位數）；`tests/sim` 0 次被拒；`npm test`、`npm run build` 通過。

- 精細的傷害平衡與關卡設計（使用者：後續再細磨）。
- 美術：沿用佔位圖形與現有貼圖流程。
