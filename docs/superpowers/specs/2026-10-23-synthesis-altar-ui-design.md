# 核心重做試玩回饋：合成台、技能樹操作、技能樹欄位

- 日期：2026-10-23
- 狀態：設計已與使用者確認，待使用者審閱本文件。
- 依據：使用者在真實瀏覽器試玩核心重做（branch `feat/core-rework`）後的回饋。
- 上層規格：`docs/superpowers/specs/2026-10-22-core-rework-design.md`（玩法）、`docs/superpowers/specs/2026-10-21-playtest-ux-fixes-design.md`（三欄版面）。本文件只改介面，**不改遊戲規則、伺服器、存檔格式與防作弊**。
- 草圖（brainstorm 時給使用者看的，HTML 片段）：`docs/design/mockups/2026-10-23-tree-actions.html`（使用者選 C，但之後拿掉上方合成列）、`docs/design/mockups/2026-10-23-altar.html`、`docs/design/mockups/2026-10-23-grimoire-col.html`。

標記說明：
- **【使用者決定】**：使用者明確說的或明確同意的。

## 1. 為什麼要改

使用者的試玩意見（原文）：

1. 好玩很多，雖各個魔法的平衡性、傷害等問題還須調整，但滿有爽快感的。
2. 基礎元素的合成表似乎失去意義了，可以考慮移除。
3. UI 介面還須調整一下：目前例如滾輪、拖拉畫面時還有點不順暢，或是衝突。
4. 合成魔法時使用選單非常不直覺。

追問後的細節：

- 合成時最卡的是**下拉選單**（「放入魔法…」），而且無法快速找到想要的魔法。使用者找魔法時靠的是**元素**，並同時參照**技能樹上的位置**。
- 使用者沒注意到節點詳情裡的「放進合成槽」按鈕；「裝備」按鈕也不直覺。兩者都藏在技能樹下方的詳情裡，視線在技能樹上時看不到。
- 使用者希望「在技能樹區塊就可以直接裝備或放入合成，而不是還要移動到其他區域點擊」，例如右鍵、快速點擊，或彈出的小泡泡。
- 技能樹縮放和頁面捲動共用滾輪；技能樹欄位上下的資訊太長，所以捲動又是必須的，兩者衝突。

**目標**：
- 在技能樹上看到一個魔法，就能在原地把它放進合成或裝備。
- 合成本身更有儀式感：看得到兩邊放了什麼、按下後有融合的特效，再揭曉結果。
- 技能樹欄位不需要捲動，滾輪在技能樹上只負責縮放。

**非目標**【使用者決定】：
- 魔法的平衡與傷害數值（之後另外調）。
- 技能樹上方的固定合成列（先不做，之後需要再補）。

**非目標**【我的決定】：不改合成規則與機率、伺服器 API、存檔格式；不做雙指縮放（`AGENTS.md` 第 8 節的已知問題，維持延後）。

**反目標**：
- 改完之後，放入合成或裝備仍要離開技能樹。
- 技能樹上滾輪仍會帶動整頁捲動。
- 合成台的特效讓結果變慢、變難懂（例如被拒絕時還要等完整動畫才知道原因）。
- 為了新特效讓戰鬥或技能樹在掉落時整個重畫（違反 `AGENTS.md` 第 6 節「React 效能」）。

## 3. 合成台（取代合成區與嘗試紀錄）

### 3.1 移除【使用者決定】

- 原本的合成區（`SynthesisPanel` 的兩個文字槽與「放入魔法…」下拉選單）。
- 「嘗試紀錄」元素×元素組合表（`SynthesisMatrix`、`matrixCell`、`crossGradeEntries` 與它們的測試）。
- 伺服器的 `synthesisLog` **保留不動**：第二版 B 會用到（核心重做帳本 R5）。【我的決定】

### 3.2 外觀【使用者決定】

- 一個大約正方形的區域，左右對半分。每一邊放一個合成輸入，並依它的**屬性與魔法**呈現不同特效。
- 「合成」按鈕在正中間（跨在左右分界上）。
- 放了東西的一邊顯示名稱與資訊；空的一邊顯示虛線和「從技能樹或元素放入」。【我的決定：文字】

各邊顯示的資訊【我的決定】：
- 魔法：元素點（`ElementDots`）、名字、`Lv.N`；強化過的另外顯示「強化 +N」（R17：Lv. 永遠是階級）。
- 元素：屬性名稱與階級（例如「火・中階」）以及背包裡的數量。
- 素材：名稱與數量。

特效的語彙【我的決定】：
- 顏色與粒子形狀沿用 `src/render/element-fx.ts`（`particleStyle`、`blendForSpell`）和 `src/render/palette.ts`，讓合成台和戰鬥畫面上的同一個元素看起來是同一種東西。
- 元素輸入用該元素的粒子；魔法輸入用魔法的元素混色（`blendForSpell`），而且要比單一元素更強烈（例如較多粒子或外圈光環），一眼分得出「放的是元素還是魔法」。
- 名魔法和自創魔法不必每個都有專屬特效；「依魔法不同」做到元素組合加上強度差異即可。
- 素材用中性的金色光點。

實作技術留給接手者決定（CSS 動畫、Canvas 2D 或小型 Pixi），限制只有：
- 不能讓戰鬥的 Pixi 畫面掉幀（右欄一直都看得到，特效會長時間播放）。
- 合成台訂閱 runtime 時用窄 selector（只訂閱兩邊放的東西、相關的背包數量、`synthPending`），不能每次掉落都重畫特效。

### 3.3 放入與取出

- 放入的來源：技能樹的泡泡與雙擊（第 4 節）、魔法筆記的「放進合成槽」、元素表點格子。一律放進**第一個空的一邊**；兩邊都滿時不動作。【沿用現有 `fillSlot` 行為】
- 兩邊都滿時，泡泡的「放入合成」按鈕顯示為停用並提示「合成台已滿」。【我的決定】
- 點一邊就把它取出（清空那一邊）。【沿用現有行為】
- 合成按鈕的啟用條件不變：兩邊都有東西、元素和素材夠、魔法都已學會、沒有正在等待的合成（`canSynth`）。
- 合成送出前照舊把輸入排序（`[...filled].sort()`），左右擺放的順序不影響結果。

### 3.4 按下合成：融合特效與結果【使用者決定：融合特效後出現結果】

流程【我的決定】：

1. 按下後，兩邊的特效往中間捲進去、兩色交融。動畫**至少** 0.8 秒；伺服器回應若比這久，就持續交融到回應到達為止。
2. 回應到達後依結果揭曉，顯示在合成台中央：

| 結果 | 合成台中央 | 之後 |
|---|---|---|
| `learned`（名魔法） | 「新發現！」＋魔法（元素點、名字、Lv.） | 照現狀自動裝備；兩邊清空 |
| `learned`（自創，`crafted`） | 「自創魔法！」＋魔法 | 同上 |
| `duplicate` | 「已經會了」＋魔法；有退還就列出退還內容，沒有就寫「沒有退還」 | 兩邊清空 |
| `noReaction` | 煙散掉的效果＋「沒有反應……材料損耗了一部分」 | 兩邊清空 |
| `dormant` | 「似乎還缺少什麼……」 | 兩邊清空 |
| `overload` | 強烈閃光＋「魔力過載！」 | 兩邊清空 |
| `rejected`（422，沒有扣東西） | **不播完整動畫**：交融立即停止、兩邊彈回原位並輕微抖動，下方顯示原因（例如「元素階級不夠，需要中階以上」） | 兩邊**保留**，讓玩家調整 |
| 回傳 `null`（忙碌、離線、衝突） | 交融停止，顯示「存檔已同步，請再試一次」 | 兩邊保留 |
| 例外（連線錯誤） | 交融停止，顯示「連線異常，請稍後再試」 | 兩邊保留 |

- 文字內容沿用 `src/ui/messages.ts` 的 `synthMessage`、`SYNTH_RETRY_MESSAGE`、`SYNTH_ERROR_MESSAGE`；畫面不可寫「全部退還」（`AGENTS.md` 第 8 節）。
- 結果停留約 2.5 秒（與 `BANNER_MS` 一致）或點一下合成台就回到空的合成台；結果的文字另外保留在合成台下方，直到下一次放入或合成。【我的決定】
- 戰鬥畫面上的 `DiscoveryBanner`（新發現橫幅）**保留**，因為玩家的視線可能在戰鬥畫面上。【我的決定】
- 揭曉期間可以放入下一個東西；放入時立刻結束揭曉、回到放入狀態。【我的決定】

## 4. 技能樹的操作

### 4.1 點節點冒出泡泡【使用者決定：C 案的泡泡】

- **單擊已學會的魔法**：節點旁浮出小泡泡，內容是元素點、名字、`Lv.N`、強化 +N（若 > 1），以及三個按鈕：
  - 「放入合成」：放進合成台（第 3.3 節）。
  - 「裝備」：等同現在的 `runtime.equip`；已裝備時顯示「裝備中」並停用；`synthPending` 期間停用（沿用現有規則）。
  - 「詳情」：打開浮動詳情卡（第 4.3 節）。
- **單擊未學會的魔法**：泡泡顯示名字（未學會）與殘卷線索，沒有按鈕。另外，線索**也**照現狀保留一份在合成台下方（`App` 的 `hintId`，點別的節點或學會之前不消失），讓玩家關掉泡泡後還能一邊看線索、一邊從元素表湊材料。【我的決定】
- **單擊被動節點**：直接打開浮動詳情卡（第 4.3 節），不經過泡泡。【我的決定，使用者同意】
- 泡泡位置跟著節點；節點靠近邊緣時要翻到另一側，不能被技能樹裁掉。
- 泡泡關閉的時機：點技能樹空白處、開始拖曳、縮放、按 Esc、點另一個節點（換成那個節點的泡泡）、按下泡泡裡的按鈕之後（「詳情」除外，它換成詳情卡）。【我的決定】
- 鍵盤：節點已可用 Tab 聚焦，Enter／空白鍵等同單擊（打開泡泡），泡泡裡的按鈕可用 Tab 走到。【我的決定】

### 4.2 雙擊快捷【我的決定】

- 雙擊已學會的魔法：直接放入合成台，節點閃一下表示已放入。合成台已滿時不動作。
- 單擊**立刻**打開泡泡（不等待判斷是不是雙擊，避免操作變遲鈍）；雙擊的第二下把泡泡關掉並放入。泡泡閃一下是可以接受的。
- 這是給熟手的捷徑；手機上沒有雙擊需求，泡泡就夠了。
- 右鍵選單不做（使用者提過右鍵，但選了泡泡方案）。

### 4.3 浮動詳情卡：詳情＋強化合而為一【使用者決定】

- 原本技能樹下方的「節點詳情」區塊（`NodeDetail`）和其中的強化（`EmpowerPanel`）合併成**一張卡片**，浮在技能樹畫面裡面（技能樹的 div 內），不再接在技能樹下方。
- 魔法的卡片內容：元素點、名字、`Lv.N`、強化 +N、相性標籤、說明；下一級強化的效果、成本與「強化」按鈕（`EmpowerPanel` 現有的內容與規則）。也保留「放入合成」「裝備」按鈕，免得打開卡片後還要回去找泡泡。【我的決定】
- 被動的卡片內容：名字、說明、條件、「解鎖」按鈕或「已解鎖」／「尚未達成條件」（`NodeDetail` 現有內容）。
- 位置：浮在技能樹底部、左右留邊（草圖 `2026-10-23-grimoire-col.html`）；卡片的內容太長時，卡片本身內部捲動，不能讓欄位捲動。【我的決定】
- 關閉：✕、Esc、點技能樹空白處。拖曳或縮放技能樹時卡片**不**關閉（玩家可能在看卡片時移動畫面找下一個節點）。【我的決定】
- 卡片開著時點另一個節點：卡片內容換成那個節點（魔法同時冒出它的泡泡，被動只換卡片）。泡泡和卡片永遠指向同一個節點，共用一份 `selected` 狀態。【我的決定】
- 魔法筆記分頁維持現狀（它有自己的按鈕與展開的強化）。

### 4.4 縮放與拖曳【使用者決定：縮放按鈕移進技能樹 div】

- 「＋」「－」按鈕從技能樹上方移進技能樹畫面裡，浮在右上角；另外加一個「⌖ 回到中心」（重設平移與縮放）。【我的決定：⌖】
- 滾輪在技能樹上只縮放，**不能**捲動頁面或欄位。React 的 `onWheel` 是被動監聽、不能 `preventDefault`，所以要用原生 `addEventListener('wheel', …, { passive: false })`。
- 滾輪縮放以滑鼠游標所在位置為中心（游標下的點縮放前後不動）；按鈕縮放以畫面中心為準。【我的決定】
- 拖曳：使用 pointer capture，拖出技能樹範圍也能繼續拖；拖曳結束時不能觸發節點的單擊或雙擊（現有的 4px 門檻與 `wasDrag` 保留）。【我的決定】
- 縮放範圍沿用現有的 `clamp`。
- **拖曳與縮放的流暢度**【我的決定】：使用者也說「拖拉畫面不順暢」。現在每次 `pointermove` 都 `setPan`，整個技能樹 SVG 跟著重新 render。改成拖曳與滾輪縮放期間不經過 React state，直接改 SVG 的 `viewBox`（或一個外層 `<g>` 的 transform），放開或停止滾動後再同步回 state；加一個測試確認拖曳期間節點不會重新 render（比照現有 Profiler 測試）。

## 5. 關鍵道具按鈕移到戰鬥畫面【使用者決定】

- 「使用○○」按鈕（`GrimoirePanel` 的 `.key-items`）移到戰鬥畫面上，並且更顯眼：金色發光的大按鈕，疊在戰鬥畫面下方中央，有一行小字說明作用（例如「驅散魔導書的迷霧」，取自關鍵道具的 `desc`）。【我的決定：位置與樣式，草圖 `2026-10-23-grimoire-col.html`】
- 只有在有可用的關鍵道具時才出現；同時有多個時並排或上下排列。顯示條件沿用現有的 `keyList` selector（背包有、而且它要揭開的區域還沒揭開）。
- `synthPending` 期間停用（沿用現有規則）。
- 使用後：中間欄的技能樹照舊播放迷霧散開的動畫（`lifting`）。如果當下在「魔法筆記」分頁，就自動切到「技能樹」分頁，讓玩家看到迷霧散開。【我的決定】
- 「迷霧散開了」的訊息顯示在戰鬥畫面上，幾秒後自動消失（順便解決 `AGENTS.md` 第 8 節「提示不會自動消失」）。失敗訊息同樣顯示在戰鬥畫面上。【我的決定】
- 這個按鈕要能在手機的戰鬥畫面高度（`max-width: 767px` 時 25vh、最低 140px）裡完整按得到。

## 6. 欄位高度與窄畫面

- 寬畫面（≥1100px）：中間欄＝分頁列＋技能樹，技能樹填滿剩下的高度（不再是 `aspect-ratio: 1` 接在詳情上方）；整欄不需要捲動。
- 右欄：合成台在上方，最大邊長受欄寬和欄高限制（保持正方形，不能把元素表擠到看不到）；元素表在下方。右欄內容超過高度時，右欄自己捲動（右欄沒有滾輪縮放，不衝突）。【我的決定】
- 手機（<768px）現在把工作台排在魔導書上方，從技能樹放入時看不到合成台。這次**維持這個排法**（上方合成列是使用者決定的非目標），但放入時在技能樹裡顯示一個短暫提示（例如「已放入合成台：烈焰爆發」，約 1.5 秒），讓玩家知道放進去了。若使用者之後覺得手機上仍不順，再討論補回合成列。【我的決定】
- 窄畫面（<1100px，欄位改成上下堆疊、整頁捲動）：技能樹給固定高度（建議約 `min(70vh, 欄寬)`），滑鼠在技能樹上時滾輪仍然只縮放；其他地方照常捲動頁面。【我的決定】
- `App.tsx` 現在的註解「<768px 合成槽在技能樹上方被捲出畫面，節點詳情重複顯示線索」：線索改到泡泡後，這個註解與重複顯示的處理一起更新。

## 7. 不能違反的規則（摘自 `AGENTS.md` 第 6 節，與本次相關）

- 伺服器是銀行：合成、強化、使用關鍵道具、解鎖被動都還是伺服器動作；介面只是換位置與外觀。被拒絕的動作回 422、不寫入。
- React 效能：技能樹與詳情卡用窄 selector；泡泡、詳情卡、合成台都不能訂閱整個 `game` 或背包。現有的 Profiler 測試必須繼續通過，新元件比照辦理。
- 「Lv.」永遠是魔法／魔物階級；強化顯示成「強化 +N」（R17）。
- 介面文字用繁體中文。

## 9. 驗收

在瀏覽器（headless 或真實）確認：
1. 在技能樹單擊已學會的魔法 → 泡泡 → 「放入合成」，合成台那一邊出現該魔法與特效；「裝備」後戰鬥畫面換成該魔法。
2. 雙擊另一個魔法直接放進合成台另一邊；按中間的「合成」→ 融合特效 → 中央出現結果。
3. 元素表點元素可放進合成台；元素輸入與魔法輸入的特效看得出差別。
4. 被拒絕的合成（例如元素階級不夠）不播完整動畫、兩邊保留、顯示原因。
5. 滑鼠在技能樹上滾動滾輪，只有技能樹縮放，頁面與欄位都不捲動；縮放以游標為中心；⌖ 回到中心。
6. 拖曳技能樹、拖出範圍再放開，不會誤開泡泡；拖曳時泡泡關閉、詳情卡保留；拖曳與縮放順暢，期間節點不重新 render。
7. 詳情卡在技能樹裡浮動顯示，可以直接強化；被動節點可以直接解鎖。
8. 有關鍵道具時，戰鬥畫面出現金色按鈕；按下後技能樹迷霧散開（從魔法筆記分頁也會切過去），訊息幾秒後消失。
9. 寬畫面中間欄不需要捲動；窄畫面（1000px、375px）版面不破、按鈕都按得到。
10. 原本的下拉選單與嘗試紀錄已不存在；`npm test` 與 `npm run build` 通過。
