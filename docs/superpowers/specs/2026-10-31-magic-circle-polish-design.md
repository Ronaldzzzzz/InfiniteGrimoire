# 魔法陣質感與手感改版（設計規格）

日期：2026-10-31　狀態：使用者 2026-11-03 確認（含第 8 節修法、素材用 AI 生成）；計畫 `docs/superpowers/plans/2026-11-03-magic-circle-polish.md`　branch：`feat/magic-circle`（尚未合併）
來源：使用者試玩回饋與四輪討論，逐字紀錄在 `2026-10-31-magic-circle-playtest-feedback.md`。
範圍：只改**外觀與操作**，加上一個 bug 修正；**不改** `src/engine` 的魔法陣規則、伺服器合成、防作弊、存檔格式。

## 1. 目標與不做的事

目標：讓魔法陣像「在昏暗書房裡攤開一張老羊皮紙，用墨與金線畫陣」，擺陣與合成有儀式感、星圖有星座感。

不做：換遊戲引擎（介面維持 React＋SVG）；聲音（暫時跳過）；改規則數字；改動畫速度與跳過方式（暫時保留現狀：合成 3 秒、稀有 5 秒、揭曉點一下跳過）；三環與專案 3（手氣、異變）。

## 2. 整體色調與羊皮紙

- 右欄（魔法陣所在區）改成**木屋、書房、昏暗**的質感：暗褐木紋桌面、局部暗角、微弱燭光色的環境光；仍維持整體深色，與戰鬥畫面不衝突。符文綠與琥珀金保留作為強調色。
- 魔法陣畫在**直立、破邊、邊緣有些微捲曲**的羊皮紙上（使用者的參考：直立破邊紙＋橫向卷軸的捲曲感，兩者合併）。
- 做法：一張完整的羊皮紙圖片當底（捲曲處的陰影與翹起感用圖片，不用 CSS 硬畫），SVG 魔法陣畫在圖上；紙面可再疊一層 SVG 濾鏡（`feTurbulence`）讓墨線邊緣略粗糙。
- **素材：** `public/assets/` 目前沒有任何貼圖。參考的兩張 pngtree 圖只作風格參考，**不進版本庫**（有浮水印與授權限制）。使用者 2026-11-03 決定：**AI 繪圖生成**，提示詞寫進 `docs/art-assets.md`，圖由使用者生成後放進 `public/assets/`。沒有素材時先用 SVG 漸層加濾鏡做的暫代紙張，素材到位後只換圖檔，程式不動。
- 手機寬度：紙張等比縮放，仍要能完整看到陣與預測。

## 3. 格子開放與排列

- **只畫已開放的格子**：連線、五芒星底線、未開放的格子**完全不顯示**（不再有淡淡的導引線）；環線也隨開放才出現。
- 開放格數＝`unlockedTier − 1`（扣掉核心），再受核心元素上限限制；一環先開，滿五格後二環才開（規則不變）。
- 一環依「已開放格數」排成對稱形狀，**放入元素時圖形不跳動**：1 個＝置於上方；2 個＝上下平分；3 個＝正三角形；4 個＝菱形；5 個＝五芒星。
- 二環同樣依已開放格數（1～4）對稱排列，並對齊一環（朝同方向向外）。
- **規則不動**：節點仍佔用原本五格序號（0～4），相生＝相鄰、相剋＝星線的判斷與伺服器一致。外觀只是把已開放的格子重新排成對稱形狀；視覺上相鄰與規則上相鄰可能不一致，**先這樣，之後不順手再改**（使用者 2026-10-31）。為了不讓玩家被誤導，畫在陣上的相生、相剋線**依規則的關係畫**（相生一種樣式、相剋一種樣式），不是依外形畫。
- 需要新增一個純函式：由「已開放格數、環別」回傳各格序號的畫面位置，單元測試涵蓋 1～5 與二環 1～4。

## 4. 放入元素：格子周圍的元素圈

- 點空格（或核心）：在那一格周圍長出一圈元素符號，順序依**相生圓**（水→土→火→雷→風），有庫存的亮、沒有的暗；選定元素後，再選階級（顯示持有量與階級名稱）。全部在紙上完成，不再有平鋪的文字選單，也不需要拖曳（元素背包在面板下方，往上拖不順）。
- 核心的元素圈同樣操作，階級選項旁顯示「上限 Lv.N」。
- 二環格不夠階級時（需要高階以上）該階級顯示為暗並說明原因。
- 已有元素的格子：再點可更換或移除（行為不變）。
- 手機：元素圈放大、不被紙邊裁掉；點圈外或按 Escape 關閉，焦點與鍵盤操作（方向鍵、Enter）保留。

## 5. 符文：一整圈符文帶

- 每環一個符文（規則不變），畫成**沿該環一整圈的符文帶**，位於該環的線上或緊貼其外側；一環與二環各一條。
- 點符文帶：整圈亮起，周圍長出符文供選擇（與元素圈一致）；未取得的符文暗並提示「從魔王取得」。
- 符文帶只在該環已開放時顯示；選定的符文以手繪風字形沿圈排列，並在合成前微微發光。
- 預測仍**不顯示形態**。

## 6. 擺陣與合成的演出

- **放入元素：** 墨水暈開、符號慢慢浮現為主，再以金光讓連到鄰格的線條自己連起來。
- **迴路對不上：** 對不上的相剋連線變紅並閃動，法陣微微震動（不要太嚇人）；文字警告保留。
- **合成中（3 秒；稀有 5 秒）：** 保留「注入魔力」的感覺，結合「線條依序亮起、最後一筆是核心」與「整張紙發光、浮起」；符文帶旋轉並越轉越快。
- **成功：** 光柱升起，揭曉面板照舊。
- **大失敗：** 要有挫折感、像真的炸了：紙面閃光後紙邊焦黑、墨線碎裂；陣保留（可再試），焦黑痕跡在下一次擺放時消退。
- **稀有魔法的 5 秒：** 與一般明顯不同：紙面出現星空、周圍畫面變暗只留魔法陣。
- 全部以 SVG 與 CSS 完成；特效數量沿用既有上限觀念，不新增無上限的粒子。

## 7. 星圖

- **扇區順序改成相生圓**（水→土→火→雷→風），只改 `src/ui/star-layout.ts` 的扇區排列（不動 `ELEMENT_ORDER`，其他地方仍用它）。相鄰元素的魔法落在兩區之間（例：流水魔彈‧風：水與風在相生圓上相鄰，落在兩區之間）；不相鄰的兩元素魔法落在它們之間那個元素的扇區（短弧），單元素魔法仍在自己的扇區；元素相互抵消（五元素齊全）時退回核心元素的扇區（現行行為）。
- 視覺改成**星座感**：星點發光、有標籤；**連線預設不顯示，選中某個魔法時才顯示它的連線**（解決學會上百個陣時一團亂）。
- **自創與教科書的差別加大：** 教科書魔法＝墨印；自創魔法＝發光的星（取代目前的琥珀金光環）。
- 手機（390 px）的星圖與詳情卡太小、被框住的問題，一併列入驗收。

## 8. Bug：合成還在跑時，星圖已經知道結果

- 原因（已查證）：`sync.ts` 的伺服器回應一到就 `runtime.replaceState`，新存檔（含 `learned`）立即進全域狀態，星圖馬上畫出新星；`CircleTable` 的 `later(...)` 只延後揭曉面板與裝備通知。稀有魔法因此先於 5 秒揭曉被劇透。
- 修法（使用者同意）：**動畫期間，星圖暫時不顯示這次剛學會的那顆星**（只擋該魔法的 id）；揭曉完成（或被跳過、被取消）後才顯示。元素存量照常扣除（不影響劇透）。不改同步流程，不碰防作弊。
- 要涵蓋：一般成功、稀有、「已知」（`known`）、大失敗（沒有新星）、動畫被卸載或換帳號時不會讓星永遠被藏住；測試要有。

## 9. Pixi 特效層（有條件，不是第一階段）

- 介面、版面、點擊維持 React＋SVG，**不換引擎**。
- 先完成第 2～8 節；只有在 SVG 與 CSS 做不出想要的華麗度（大量粒子、光暈、符文漂浮）時，才在魔法陣上疊一層透明的 Pixi 畫布專畫特效，重用戰鬥長帶的 Pixi 基礎與 `MAX_ACTIVE_FX` 上限。是否做由使用者看過第一階段後決定。
