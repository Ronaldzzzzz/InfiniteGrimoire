# 第二版路線：拆分、順序與待決問題

- 日期：2026-10-21
- 依據：上層規格 `docs/superpowers/specs/2026-10-21-infinite-grimoire-design.md` 第 4.11、4.13、4.14 節與第 6 節「不包含：第二版」。
- 狀態：拆分與順序已由使用者確認；A 的 spec 與計畫已完成；B、C+D 尚未開始設計。

## 1. 拆分【使用者決定】

上層規格的第二版包含四個彼此獨立的子系統，拆成三個子專案，每個各自走「設計討論 → spec → 計畫 → 實作」：

| 順序 | 子專案 | 內容 | 狀態 |
|---|---|---|---|
| 1 | **A 帳號綁定** | 帳號＋密碼、多裝置登入、改密碼、登出；登入與遊客建立的頻率限制 | spec：`2026-10-21-v2a-accounts-design.md`；計畫：`docs/superpowers/plans/2026-10-21-v2a-accounts.md`；**待執行** |
| 1b | **A2 Google 登入** | Google Identity Services ID token，只存 `sub` | 使用者決定這次不做；之後另開。需要使用者在 Google Cloud Console 建立 OAuth 用戶端並提供 client ID |
| 2 | **B 稀有魔法發現紀錄** | 機率 ≤10% 的變異結果：首位發現者（永久）、最近發現動態；只顯示魔法名稱、殘卷線索與發現者**顯示名稱**，不公布配方 | 未開始。伺服器已有 `synth_events`（每次合成的組合與結果），可以直接當資料來源 |
| 3 | **C+D 排行榜與至尊稱號** | 各屬性排行；每天 UTC+8 午夜以 Cron Triggers 結算五個屬性的至尊稱號 | 未開始。**先解決下面第 2 節的兩個問題** |

## 2. C+D 開始前必須先決定的問題

1. **至尊稱號的資格依賴「大魔導士稱號」**。上層規格 4.14：資格是「已取得該屬性的大魔導士稱號，所以也必須遵守『不學其他屬性魔法』的限制」。但稱號系統（4.4 的稱號與限制條件）被排在「之後」，不在第二版。選項：
   - 把「大魔導士稱號」這一部分提前到 C+D 一起做。
   - 或第二版先放寬資格（例如只看該屬性的進度，不檢查是否學過其他屬性），等稱號系統完成再收緊。
2. **目前內容太少，排名很快就會同分**。每個屬性只有 3 個魔法節點、3 個地點；規格的比較方式是「該屬性已啟動節點數 → 打倒的最高魔王階級 → 先達到者」，前段玩家約 1 小時內就會全部同分，最後只剩「誰先達成」。選項：
   - 等內容（魔法、地點）增加後再做排行。
   - 或改用其他排名依據（例如稀有魔法數、某段時間內的擊殺數）——這會改上層規格，需要使用者同意。

## 3. 所有子專案共通的規則

- 不收集 email；公開顯示一律用**顯示名稱**，不顯示帳號名稱。
- 可疑帳號（`players.suspicious`）不上發現紀錄的「首位發現者」、不參加排行與至尊結算（上層規格 4.12、4.14）。
- **不部署**：等使用者明確指示才上線（2026-10-21）。
- **不主動 push**：使用者會自己 push。
