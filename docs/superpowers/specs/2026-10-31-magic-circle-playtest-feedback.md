# 魔法陣（專案 2）試玩回饋（2026-10-31）

狀態：只記錄與找原因，**尚未決定修正方式，沒有計畫、沒有改程式**。branch `feat/magic-circle`。

## 回饋與原因

1. **風格太現代、沒有神秘感。** 牛皮紙上是 CSS 圓線＋圓形按鈕＋文字字形（`CircleTable.tsx`、`circle-draw.ts`），節點是 UI 按鈕的樣子。待釐清想要的方向（見提問）。
2. **Lv.0 就看到完整五芒星。** `CircleTable.tsx:337` 的 `<path className="guide" d={starPath()}>` 無條件繪製，不看 `circleTier`／已開放格子；兩個環線（335、336）也一樣。開局只開放核心＋少數格，畫面卻已是完整終局圖形。
3. **符文不明顯、不在陣上。** 現在符文是陣下方的「一環符文／二環符文」兩顆按鈕（`rune-row`，399～401 行），點了跳出選單；SVG 裡完全沒有符文圖形。原構想是符文位於**節點與節點之間**，現行規則是「每環一種符文」，兩者模型不同（見提問）。
4. **放入核心／節點是選單，不易懂、排序亂。** `Picker`（`CircleTable.tsx:471`）列出「元素×階級」全部有庫存的組合，順序是 `ELEMENT_ORDER`（火風雷土水）× 階級，以純文字按鈕平鋪（例「火・初階 ×12」），核心還要附「上限 Lv.N」。沒有分組、沒有和左側元素表的連結，庫存多了就是一大串。
5. **星圖位置不對（流水魔彈・風 出現在火區）。** 原因已確認：`star-layout.ts` 的 `starPosition` 取各元素扇區角度的向量平均，扇區順序是 `ELEMENT_ORDER`（火 36°、風 108°、雷 180°、土 252°、水 324°）。水（324°）與風（108°）在圓周上**不相鄰**，中間隔著火，平均角度正好落在 36°＝火的扇區。這是既知限制（AGENTS 3.0 Ruling 7：「不相鄰元素的魔法會落在第三個元素的扇區」），不是偶發錯誤；另外扇區順序（火風雷土水）也不是魔法陣上的相生順序（水→土→火→雷→風），兩套圓周排列不一致。

## 新發現的 bug：合成還在跑時，星圖已經知道結果

**現象：** 按下合成後，魔法陣還在 3 秒（稀有 5 秒）的動畫，左方星圖就已經出現新魔法。

**原因（已查證）：** 伺服器一回應，`SyncController`（`src/game/sync.ts:307`）立刻 `runtime.replaceState`，新存檔（含 `learned`、元素扣除）馬上進全域狀態，星圖用這個狀態畫，所以新星立刻出現。`CircleTable.tsx:285` 的 `later(...)` 只延後了**揭曉面板與 `onResult`（裝備通知）**，沒有延後存檔本身。稀有魔法也一樣，先於 5 秒的全螢幕揭曉就被劇透。元素存量也是一回應就扣掉。

**要釐清的取捨（尚未決定修法）：** 方向有二：(a) 動畫期間暫時隱藏「這次剛學會的魔法」的星（只擋學會的 id，元素扣除照常）；(b) 延後採用伺服器存檔直到揭曉。(a) 小而單純、不影響同步與防作弊；(b) 動到同步流程。
