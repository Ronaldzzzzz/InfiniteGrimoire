# 上線前檢查清單

- 建立：2026-10-22
- 用途：記下「現在不做、上線前要重新看一次」的基礎建設項目。使用者決定目前不再投入基礎建設，**上線前統整一次，逐項決定要不要修正**。
- 原則：小型非營利遊戲，安全性做到合理即可（不追求滴水不漏）。

## 1. 部署當下必做

- [ ] 遠端 D1 依序套用 migration 0001～0007（0001→0002→0003→0004→0005→0006→0007，一個都不能跳）；套用 0003 前先備份（0003 會重建 `players` 表）。**0005、0006 都必須在新的 worker 部署之前套用**：現在每次讀玩家都會讀 `players.gm_used`（0006 新增的欄位），沒套用 0006 時，凡是會讀玩家資料的請求都會 500（健康檢查與建立遊客仍可運作，但遊戲本身不能玩）。
- [ ] **遠端 D1 要套用 0007（橫向戰鬥帶與關卡：`currentStage`／`clearedStages`／`lastClearAt`、移除 `zoneKills`），它會重置所有存檔**（舊的以擊殺數推進的存檔格式不相容）。必須在新的 worker 部署之前套用（新 worker 讀不了舊存檔格式）；套用前先備份並確認沒有需要保留的玩家，已綁定帳號的帳號與密碼不受影響、進度歸零。
- [ ] **遠端 D1 要套用 0004（核心重做），它會重置所有存檔**（舊玩法的存檔格式與內容都不相容）。套用前先備份並確認沒有需要保留的玩家；已綁定帳號的帳號與密碼不受影響，但進度會歸零。
- [ ] 遠端 D1 要套用 0005（第二版 B 的 `discoveries` 表）。0005 只新增資料表與索引，**不會重置存檔**；套用後確認 `discoveries` 與 `discoveries_first` 唯一索引都在。
- [ ] **顯示名稱去除控制字元、雙向文字控制字元（bidi）與零寬字元**（第二版 B 起顯示名稱會出現在每位玩家的發現動態裡，可用來偽裝或打亂版面）：建立遊客與改名時在伺服器過濾或拒絕，並處理已存在的名稱。
- [ ] 遠端 D1 要套用 0006（GM 工具：`players.gm_used`、`gm_tokens`、`gm_actions`）。0006 **不會重置存檔**；套用後確認既有玩家與存檔筆數沒變、`gm_used` 預設 0。
- [ ] **GM 名單最後才設**：第一次部署時**不要**設定 `GM_USERNAMES`（這時 `/api/gm/*` 一律 404，功能等於不存在）；部署後在上線的遊戲裡用強密碼綁定 GM 帳號，綁定完成後才 `npx wrangler secret put GM_USERNAMES`，填 GM 帳號名稱（逗號分隔；設定 secret 會自動重新部署）。**只列已經綁定在你自己名下的帳號名稱**：GM 身分是「誰先綁定這個名稱」，列了但還沒人綁定的名稱，任何人都能搶先綁定而成為 GM；名單裡格式不合法的名稱會被忽略。之後要加 GM 也一樣：先綁定、再改名單。已知限制：配方表在前端 bundle 裡，GM 視窗隱藏配方表只是介面上的，不是安全邊界。
- [ ] **決定稀有魔法的刷取時間**（AGENTS.md 第 3 節待辦 0a）：目前量測 139～211 模擬分鐘，高於設計上限 120；上線前由使用者決定接受或調整權重／成本。
- [ ] `npx wrangler secret put PASSWORD_PEPPER`，填隨機長字串。
- [ ] **另外保存一份 pepper**（例如密碼管理器）。Cloudflare secret 設定後讀不回來；pepper 上線後不能更換，換了所有帳號都無法登入。
- [ ] 確認 D1 Time Travel（時間點還原）在目前方案的保留天數，決定是否還需要定期匯出備份。
- [ ] 開啟 Workers Logs，讓伺服器的 500 錯誤看得到（目前程式出錯只回 500、不寫紀錄；紀錄中不可出現密碼雜湊或 token）。

## 2. 忘記密碼（不收 email，規格的取捨）

玩家沒有自助找回密碼的方式。做法是**用 GM 工具的「玩家」分頁重設**（`docs/superpowers/specs/2026-10-23-gm-tool-design.md` 第 5.4 節）：GM 輸入玩家的帳號名稱，工具在瀏覽器產生 12 字元臨時密碼並只顯示一次；伺服器登出該玩家所有裝置、清掉登入失敗限制、寫入 `gm_actions` 紀錄（沒有明文密碼）。把臨時密碼轉交玩家，請對方登入後立刻改密碼。不能重設自己或 GM 名單中的帳號。

上線前要完成：
- [ ] **【必做】用 GM 工具在本機 D1 測一次重設**：先綁定本機的 GM 測試帳號，再把**已綁定的**名稱寫進 `.dev.vars` 的 `GM_USERNAMES`，重設另一個測試帳號後確認舊密碼不能登入、臨時密碼可以登入（即使該帳號先前因連錯被鎖住）、原本登入的裝置被登出。（2026-10-23 已在本機驗收通過一次；上線前以最終版本再測一次。）

上線前要決定：
- [ ] 「確認是擁有者」的依據。沒有 email，只能問對方知道的資料：顯示名稱、大約建立日期、已學的魔法、目前地點、背包內容等（都可在 `saves` 與 `players` 查到）。這種方式無法完全防冒名，對小型遊戲可以接受。
- [ ] 是否改成玩家自助的「恢復碼」（綁定時顯示一次，只存雜湊）。

## 3. 延後的小問題（帳本 `docs/superpowers/sdd/2026-10-21-v2a-accounts/progress.md` 的 `minor (deferred)`）

- [ ] 帳號對話框內收到 401 只顯示「發生錯誤」，最多 30 秒後才回到開始畫面。
- [ ] `/api/guest` 每 IP 每小時 10 個的限制不是原子操作，並發請求可能超過。
- [ ] 登出前的最後一次上傳在上傳中、重試中或合成中會被跳過，最後幾秒進度可能遺失。
- [ ] 沒設 pepper 時，登入不存在的名稱回 403、存在的回 500，可看出名稱是否存在（只在設定錯誤時）。
- [ ] 非 HTTPS（例如手機以 `http://192.168.x.x` 連本機試玩）時瀏覽器沒有 `crypto.subtle`，綁定／登入只顯示「發生錯誤」。
- [ ] 沒設 pepper 回 500 只測了綁定，登入與改密碼沒測。
- [ ] 舊版前端送明文密碼時，畫面顯示「密碼需要 8～128 個字」，原因說明不準確。
- [ ] 已知取捨（確認仍可接受即可）：任何人可用 5 次錯誤登入鎖住某名稱 15 分鐘；綁定時 409 `taken` 透露名稱已存在；綁定沒有頻率限制。

## 4. 之後（做到相關功能時才處理）

- 遊戲內容（魔法、地點 JSON）改版時，舊存檔的相容與搬移。
- 第二版 C+D：Cron Trigger 每日結算。
- 離線收益：已實作（2026-10-30，伺服器計算）。新欄位 `clearTimes`、`awayAt`、`offlineUntil` 有預設值，**不需要新的 migration**（遠端仍只要 0007）。
- 第三版市集：購買原子化、每人限買一次、金幣不能複製。
- A2 Google 登入（需要使用者建立 OAuth 用戶端）。
- 之後任何會重建 `players` 表的 migration（像 0003 那樣複製 → DROP → 重建）都要處理 `discoveries.player_id` 指向 `players(id)` 的外鍵：先備份並暫存 `discoveries`，或在重建期間關閉外鍵檢查，否則 DROP 會失敗或遺失發現紀錄。
